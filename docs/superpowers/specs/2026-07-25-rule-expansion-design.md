# 감지력 고도화 — 맞춤법 규칙 대량 확장 (51 → ~150종)

- 상태: 설계 승인 (2026-07-25)
- 대상 버전: v0.3.0
- 선행: v0.2.0 (교차 프로세스 IME 수정, 규칙 51종)

## 1. 배경 & 목표

현재 감지 엔진은 **정규식 단어 매칭 51종**(Certain 45 · Suspect 4 · Info 2)이다. 명백한 오타에는 강하지만 커버 범위가 좁다. 이 작업은 규칙을 **약 150종으로 확장**해 감지력을 끌어올리되, 이 앱의 **절대 원칙인 "오탐 제로"를 자동으로 지키는 구조**를 함께 도입한다.

**성공 기준**
- 규칙 총 ~150종(신규 ~100종 추가).
- 신규 규칙 전부가 감지 테스트를 통과.
- **정상 한국어 코퍼스 + 모든 규칙의 정상 예시에서 Certain/Suspect 감지 0건**(오탐 제로).
- 런타임 성능·앱 크기·개인정보 원칙에 영향 없음.

## 2. 범위

**포함**
- 규칙 포맷에 자가검증용 선택 필드(`examples`, `okExamples`) 추가.
- 규칙 파일을 신뢰도 3분할 → **범주별 파일**로 재편(기존 51종 무손실 이관).
- 데이터 주도 오탐 게이트 테스트 2종 + 공유 정상 코퍼스.
- 4개 범주에 걸친 신규 규칙 ~100종.

**제외(YAGNI)**
- 띄어쓰기 검사(오탐 위험 큼 — 사용자가 명시적으로 배제).
- 사전/형태소 기반 "없는 단어" 탐지(별도 프로젝트).
- 규칙 GUI 편집기, 성능 최적화(트라이/Aho-Corasick) — 현재 규모에선 불필요.

## 3. 접근 (승인된 A안)

"자가검증 범주 파일" 방식. 규칙에 예시를 붙이면 그 예시가 곧 테스트가 되어, 규칙이 늘어도 오탐 회귀가 자동으로 차단된다. 규칙 = 문서 = 테스트가 항상 일치.

## 4. 상세 설계

### 4.1 규칙 포맷 확장

`Rule` 레코드(`src/HangulNotifier.Core/Rules/Detection.cs`)에 **선택 필드 2개** 추가:

```csharp
public sealed record Rule(
    string Id,
    string Pattern,
    string Suggestion,
    string Message,
    Confidence Level,
    string? PreviousWordPattern = null,
    string? PreviousWordNotPattern = null,
    IReadOnlyList<string>? Examples = null,      // 신규: 반드시 감지돼야 하는 오류 표기
    IReadOnlyList<string>? OkExamples = null);   // 신규: 절대 감지되면 안 되는 올바른 표기
```

JSON 예:
```json
{
  "id": "meseji", "pattern": "메세지", "suggestion": "메시지",
  "message": "'메시지'가 바른 외래어 표기입니다.", "level": "Certain",
  "examples": ["메세지", "메세지를", "음성메세지"],
  "okExamples": ["메시지", "메신저"]
}
```

- `examples`/`okExamples`는 **테스트 전용 메타데이터**. `RuleEngine.Check()`는 참조하지 않는다(런타임 동작·성능 영향 0).
- `RuleSet` 역직렬화는 System.Text.Json이 선택 필드를 자동 처리(누락 시 null).
- 신규 규칙은 `examples`를 최소 1개, 오탐 위험이 있는 규칙은 `okExamples`를 필수로 채운다.

### 4.2 파일 재편 (범주별)

기존 `Rules/{certain,suspect,info}.json` → 범주 파일로 이관. 임베디드 리소스 글롭 `Rules\**\*.json`이 이미 하위 폴더를 포함하므로 코드 변경 없이 인식된다. 각 규칙은 자기 `level`을 가지므로 범주 파일 안에 신뢰도가 섞여도 무방하다.

| 파일 | 내용 |
|---|---|
| `Rules/doe-dwae.json` | 되/돼, 되어 준말, 안 돼/않, 봬/뵈 등 |
| `Rules/impossible-syllables.json` | 됬·됀·됌·됄·몆·옜 등 존재 불가 음절 |
| `Rules/standard-words.json` | 역할·어이없다·희한·오랜만·설렘·구시렁 등 표준어 오표기 |
| `Rules/loanwords.json` | 메시지·초콜릿·로봇·액세서리·콘텐츠 등 외래어 |
| `Rules/sai-siot.json` | 오랫동안·등굣길·순댓국·초점(촛점) 등 사이시옷 |
| `Rules/vowel-confusion.json` | 금세/금새, 왠지/웬지, ㅐ/ㅔ·ㅚ/ㅙ 혼동 |
| `Rules/endings-colloquial.json` | -ㄹ게(-ㄹ께), -고요(-구요), 든/던, 대/데 등 |

이관 시 기존 51종의 `id`·`pattern`·`suggestion`·`message`·`level`·`previousWord*`를 **그대로 보존**한다. `id` 중복 금지.

### 4.3 오탐 게이트 (핵심)

`tests/HangulNotifier.Rules.Tests/`에 데이터 주도 테스트 추가:

1. **모든 규칙 감지 검증** — `RuleSet.LoadDefault().Rules`를 순회하며, 각 규칙의 `examples`가 (전 규칙을 켠 엔진에서) **그 규칙을 발동**시키는지 확인. (Info 규칙은 Info 활성 엔진으로 확인)
2. **정상 코퍼스 오탐 0** — 공유 정상 코퍼스(올바른 한국어 단어·짧은 문장 ~300개) + 모든 규칙의 `okExamples`를 합쳐, 기본 설정(Certain+Suspect 켬, Info 끔) 엔진에서 **감지 0건**인지 확인. 하나라도 걸리면 실패.
   - 코퍼스는 `tests/HangulNotifier.Rules.Tests/Corpus/valid-korean.txt`(한 줄 하나)로 관리, 임베디드 리소스로 로드.

정상 코퍼스에는 특히 **오탐을 유발하기 쉬운 정답들**을 포함한다: 된다·됨·될·됐다·돼요·돼서, 며칠·몇월, 메시지·메신저, 초점, 오랫동안, 돼지(동물, Info라 기본 감지 안 됨 확인) 등.

### 4.4 신뢰도 정책

| 레벨 | 기준 | 예 |
|---|---|---|
| **Certain** | 존재 불가능 음절 또는 항상 틀린 표기(문맥 무관) | 됬→됐, 메세지→메시지, 역활→역할 |
| **Suspect** | 문맥에 따라 맞을 수 있음(기본 ON, 신중히) | 되(문장끝)→돼, 든지/던지 |
| **Info** | 실제 단어와 충돌 가능(기본 OFF) | 돼지, 되게 |

애매하면 한 단계 낮춘다. Certain은 오탐 0이 증명되는 것만.

### 4.5 신규 규칙 ~100종 배분

각 항목은 구현 시 `examples`/`okExamples`와 함께 작성. 아래는 대표 예(전체는 구현 계획에서 확정).

- **자주 틀리는 표준어 ~35**: 삼가하다→삼가다, 절대절명→절체절명, 어물쩡→어물쩍, 흐리멍텅→흐리멍덩, 뒤치닥거리→뒤치다꺼리, 우겨넣다→욱여넣다, 개구장이→개구쟁이, 넉두리→넋두리, 발자국(발자욱), 애띠다→앳되다, 두리뭉실→두루뭉술 등.
- **불가능 음절 ~15**: 됀·됌·됄(v0.2.0 완료) 외에, 한국어에서 나타날 수 없는 음절만 선별해 추가한다. 판정 기준: 해당 음절이 표준국어대사전 표제어·활용형 어디에도 등장하지 않을 것. 후보는 구현 시 개별 검증 후 확정하며, 조금이라도 실재 가능성이 있으면 **채택하지 않는다**(예: `됏`처럼 오타로만 보이는 것도 실제 용례 확인 후 결정).
- **외래어 ~30**(괄호가 틀린 표기): 메시지(메세지), 초콜릿(초콜렛), 로봇(로보트), 액세서리(악세사리), 리더십(리더쉽), 콘텐츠(컨텐츠), 소시지(소세지), 스케줄(스케쥴), 주스(쥬스), 콘셉트(컨셉), 배터리(밧데리), 뷔페(부페), 앰뷸런스(앰블런스), 렌터카(렌트카), 프레젠테이션(프리젠테이션), 디지털(디지탈), 비전(비젼), 도넛(도너츠), 카페(까페), 텔레비전(텔레비젼) 등.
- **사이시옷·모음 ~20**(괄호가 틀린 표기): 등굣길(등교길), 순댓국(순대국), 만둣국(만두국), 북엇국(북어국), 나뭇가지(나무가지), 장맛비(장마비), 최댓값(최대값), 초점(촛점), 베개(배개), 헤매다(헤메다), 설레다(설레이다), 널따랗다(넓다랗다) 등.
- **어미·구어체 ~15**: 갈게(갈께)·줄게(줄께)·볼게(볼께)·먹을게(먹을께) 등 -ㄹ께 계열, 든지/던지(Suspect), 대/데(Suspect, 문맥), 예요/에요 확장.

각 규칙은 **정상형이 절대 걸리지 않도록** `okExamples`로 방어(예: 로봇→"로봇청소기", 초점→"촛불"은 무관, 든지 규칙은 회상 '던' 정상문 포함).

## 6. 성능

`RuleEngine.Check()`는 어절 경계마다 전 규칙을 선형 스캔한다. 짧은 어절 × 컴파일 정규식 → 규칙 150종이어도 어절당 수백 µs. 타이핑 시 어절 경계는 초당 수 회이므로 부하 무시 가능. **최적화 불필요**(수천 종으로 갈 때 재검토).

## 7. 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| 신규 규칙의 오탐 | 규칙마다 `okExamples` + 공유 정상 코퍼스 게이트로 자동 차단 |
| 파일 이관 중 규칙 누락 | 이관 후 규칙 총수·id 목록을 이전과 대조하는 테스트 |
| 외래어/사이시옷의 애매함 | 애매하면 Certain 금지 → Suspect/Info |
| 구어체 어미 과잉 감지 | -구요, 대/데 등은 Suspect로, 문맥 조건 활용 |
